# PRD — AI-проверка техники упражнения по видео

## 1. Цель и контекст
- Добавить в fitTODOay функцию анализа техники выполнения упражнения по короткому видео.
- Пользователь не обязан выбирать упражнение заранее: система сама распознает движение, сопоставляет его с каталогом упражнений и дает обратную связь по технике.
- Фича должна помогать улучшать качество тренировок, но не должна позиционироваться как медицинская диагностика или полноценная замена тренера.

## 2. Основной пользовательский сценарий
1. Пользователь открывает раздел «Проверка техники».
2. Нажимает «Записать видео» или «Загрузить видео».
3. Записывает короткий ролик выполнения упражнения.
4. Backend принимает видео и запускает анализ.
5. Система автоматически определяет упражнение.
6. Если уверенность высокая, пользователь сразу получает результат.
7. Если уверенность средняя или низкая, система просит подтвердить упражнение из каталога.
8. После анализа пользователь видит:
   - распознанное упражнение;
   - оценку техники;
   - основные ошибки;
   - что исправить в следующем подходе;
   - краткую инструкцию по правильному выполнению.

### Пример результата
```text
Упражнение: Присед
Оценка техники: 72/100

Что хорошо:
- Темп движения стабильный.
- Амплитуда в большинстве повторений достаточная.

Что исправить:
- Колени немного заваливаются внутрь в нижней фазе.
- Корпус слишком сильно наклоняется вперед.

На следующем подходе:
- Направляйте колени в сторону носков.
- Держите грудь выше и сохраняйте опору на пятки.
```

## 3. MVP Scope
В MVP поддерживаем ограниченный список упражнений, для которых можно надежно анализировать технику по видео.

### Первая версия
- Присед без веса.
- Отжимания.
- Планка.
- Выпады.
- Жим гантелей стоя или сидя — опционально.
- Становая тяга с легким весом — опционально и осторожно.

Если упражнение не распознано или пока не поддерживается, система возвращает дружелюбный fallback:

```text
Не удалось надежно определить упражнение или оно пока не поддерживается для проверки техники. Попробуйте записать видео сбоку, чтобы все тело было видно в кадре.
```

## 4. Что не входит в MVP
- Анализ любых упражнений без ограничений.
- Медицинские рекомендации.
- Диагностика боли, травм, осанки или заболеваний.
- Live-feedback во время записи.
- Сравнение с профессиональными эталонными видео.
- Кастомная ML-модель, обученная на собственном датасете.
- Гарантированно точная оценка техники при плохом качестве видео.

## 5. UX требования
Перед записью пользователь видит короткие рекомендации:

```text
Для точного анализа:
- снимайте все тело целиком;
- поставьте камеру сбоку или под углом 45 градусов;
- обеспечьте хорошее освещение;
- выполните 3-5 повторений;
- не закрывайте суставы слишком свободной одеждой.
```

Ограничения видео:
- рекомендуемая длина: 5-15 секунд;
- максимальная длина MVP: 30 секунд;
- максимальный размер файла задается backend-конфигом.

Статусы анализа:
```text
uploading
processing
needs_confirmation
completed
failed
```

При `needs_confirmation` UI показывает:

```text
Похоже, это присед. Подтвердите упражнение, чтобы получить точный разбор.
```

Варианты действий:
- подтвердить предложенное упражнение;
- выбрать один из альтернативных вариантов;
- выбрать упражнение из каталога;
- отменить анализ.

## 6. Архитектура
Рекомендуемый pipeline:

```text
Frontend video upload
→ Backend stores video
→ Frame extraction / pose estimation
→ Exercise detection
→ Exercise mapping to catalog
→ Technique analysis
→ LLM summary generation
→ Structured result returned to frontend
```

LLM не должна быть единственным источником анализа техники. Базовый подход:

```text
Computer Vision / Pose Estimation
+ rule-based checks
+ LLM для объяснения результата пользователю
```

LLM отвечает за:
- распознавание упражнения, если используется vision-модель;
- генерацию понятного summary;
- формулировку советов;
- объяснение ошибок простым языком.

Backend отвечает за:
- загрузку и хранение видео;
- безопасность API-ключей;
- запуск анализа;
- сопоставление распознанного упражнения с `Exercise_DB` или `CustomExercise`;
- валидацию результата;
- логирование;
- сохранение результата.

## 7. Распознавание упражнения
Система должна вернуть распознанное упражнение, confidence и альтернативы.

Пример:
```json
{
  "detected_exercise": {
    "name": "Присед",
    "catalog_exercise_id": 12,
    "confidence": 0.86,
    "alternatives": [
      { "name": "Гоблет-присед", "catalog_exercise_id": 44, "confidence": 0.61 },
      { "name": "Выпады", "catalog_exercise_id": 21, "confidence": 0.43 }
    ]
  }
}
```

Рекомендуемые пороги:
- `confidence >= 0.75` — можно сразу запускать анализ техники;
- `0.45 <= confidence < 0.75` — показать подтверждение упражнения;
- `confidence < 0.45` — попросить выбрать упражнение вручную или переснять видео.

Пороговые значения уточняются после первых тестов на реальных видео.

## 8. Backend модель данных
Новая сущность: `TechniqueReview`.

Примерная структура:
```text
TechniqueReview
- id
- user
- exercise nullable
- detected_exercise_name
- detected_exercise_confidence
- video_file
- status
- score nullable
- result_json
- summary
- error_code nullable
- created_at
- updated_at
```

Пример `result_json`:
```json
{
  "detected_exercise": {
    "name": "Присед",
    "catalog_exercise_id": 12,
    "confidence": 0.86,
    "alternatives": ["Гоблет-присед", "Выпады"]
  },
  "score": 72,
  "issues": [
    {
      "code": "knees_caving_in",
      "severity": "medium",
      "title": "Колени заваливаются внутрь",
      "evidence": "В нижней фазе движения колени смещаются внутрь относительно стоп.",
      "advice": "Направляйте колени в сторону носков и контролируйте положение бедер."
    }
  ],
  "positive_notes": [
    "Темп движения стабильный."
  ],
  "next_set_focus": [
    "Следите за направлением коленей.",
    "Сохраняйте опору на пятки."

    "Камера установлена достаточно удачно для анализа сбоку."
  ]

```

## 9. API

### Создать проверку техники
```http
POST /api/technique-reviews/
```

Payload:
```http
multipart/form-data
video: file
```

Response:
```json
{
  "id": 101,
  "status": "processing"
}
```

### Получить статус и результат
```http
GET /api/technique-reviews/{id}/
```

Response:
```json
{
  "id": 101,
  "status": "completed",
  "exercise": {
    "id": 12,
    "name": "Присед"
  },
  "score": 72,
  "summary": "В целом техника стабильная, но стоит контролировать положение коленей и наклон корпуса.",
  "result": {}
}
```

### Подтвердить упражнение
```http
POST /api/technique-reviews/{id}/confirm-exercise/
```

Payload:
```json
{
  "exercise_id": 12
}
```

Response:
```json
{
  "id": 101,
  "status": "processing"
}
```

## 10. Логирование и безопасность
Backend должен логировать:
- ID пользователя;
- время загрузки;
- статус анализа;
- распознанное упражнение;
- confidence;
- error_code при ошибке;
- обезличенный payload анализа;
- ответ LLM без PII.

Не логировать:
- email;
- имя пользователя;
- токены;
- приватные пользовательские данные;
- публичные ссылки на видео без необходимости.

Видео должно быть доступно только владельцу. При дальнейшей реализации нужно отдельно определить срок хранения видео и возможность удаления пользователем.

## 11. Ошибки
Типовые `error_code`:
```text
video_too_large
unsupported_format
exercise_not_detected
exercise_not_supported
low_confidence
pose_estimation_failed
llm_unavailable
invalid_llm_response
analysis_timeout
```

Пользовательские сообщения должны быть дружелюбными:

```text
Не удалось разобрать видео. Попробуйте снять упражнение сбоку, чтобы все тело было видно в кадре.
```

```text
Помощник временно недоступен. Видео сохранено, попробуйте повторить анализ позже.
```

## 12. Критерии готовности MVP
Фича считается готовой, если:
- пользователь может загрузить видео;
- backend создает `TechniqueReview`;
- система определяет упражнение или просит подтверждение;
- поддерживаемые упражнения получают структурированный анализ;
- результат сохраняется и доступен повторно;
- frontend показывает статус обработки;
- frontend показывает summary, ошибки и советы;
- ошибки анализа не ломают UI;
- есть backend-тесты на успешный сценарий и fallback;
- есть ручная end-to-end проверка через UI.

## 13. Риски и открытые вопросы
1. **Качество видео** — плохой ракурс, темнота, обрезанное тело и свободная одежда резко снижают точность.
2. **Ответственность за рекомендации** — текст должен быть осторожным: «похоже», «обратите внимание», «попробуйте», а не категоричные медицинские выводы.
3. **Стоимость обработки** — видео и vision-модели дороже обычного текста; нужны лимиты и rate limiting.
4. **Асинхронность** — анализ может занимать больше нескольких секунд, поэтому нужен статус обработки и повторный опрос результата.
5. **Хранение видео** — нужно решить срок хранения, ручное удаление и возможную очистку старых файлов.
6. **Поддержка каталога** — распознанное упражнение должно приводиться к нашему каталогу, иначе результат нельзя надежно связать с тренировками.

## 14. Главный продуктовый принцип
Фича должна говорить не:

```text
Вы делаете упражнение неправильно.
```

А:

```text
Похоже, в этом подходе есть несколько моментов, которые можно улучшить.
```

Тон должен быть тренерским, спокойным и практичным: меньше критики, больше конкретного действия на следующий подход.
