# fitTODOay — Mobile PRD

## 1. Обзор
- **Цель:** выпустить мобильное приложение (iOS/Android) с паритетом ключевых сценариев веба: онбординг, управление программами, выполнение тренировок с офлайн-очередью, аналитика и AI-ассистент.
- **Стек:** React Native 0.81+ с TypeScript (типы входят в пакет начиная с 0.71, см. React Native docs), React 18, React Navigation, Zustand/Context для сессии, react-query или SWR-соответствие (для кэширования запросов), AsyncStorage для локальных данных, Reanimated для жестов/анимаций, Expo не используется.
- **API:** REST-эндпоинты Django (`/api/...`), тот же бэкенд, что и веб. Базовый URL задаётся через `.env` (`API_URL`). Авторизация токеном.

## 2. Пользовательские сценарии
1. **Landing/Auth:** экран приветствия с CTA «Войти/Создать аккаунт». Авторизация по email/паролю; при отсутствии токена любой приватный экран редиректит на `AuthStack`.
2. **Онбординг:** многошаговый мастер профиля (цель, параметры тела, ограничения, оборудование, предпочтения LLM). Данные сохраняются в профиле (`llm_preferences`) и подгружаются при повторном входе.
3. **Программы:** просмотр папок, включение/выключение, создание новой; упрощённый редактор шаблонов с расписаниями и добавлением упражнений из каталога или кастомных.
4. **Чеклист тренировки:** загрузка дневного плана, отметка подходов, Rest Timer, офлайн-очередь логов, рекомендации по корректировкам.
5. **Аналитика:** компактные карточки нагрузки, топ упражнений и график «Динамика по программам» с переключением периодов (скроллимые столбцы/линии).
6. **AI-ассистент:** запуск генерации программ через визард «Создать с помощником»; отображение списка созданных программ (одна активна).

## 3. Экраны и IA
- **Стек навигации:** `AuthStack` (Welcome/Login/Register/Onboarding), `MainTabs` с вкладками `Программы`, `Чеклист`, `Аналитика`, `Профиль`. Вкладка ассистента доступна как кнопка CTA на `Программы` или `Профиль`.
- **Программы (`/programs`):** список папок (switch активности, кнопка «+»), карточка папки открывает шаблоны. Шаблон поддерживает расписания: weekly, biweekly, interval, custom dates. Таб «Каталог/Мои упражнения» в редакторе — пока показываем общий список, но архитектурно предусматриваем разделение.
- **Чеклист (`/workout`):** дерево папка → шаблон → упражнения → подходы. Каждому сету соответствует строка с плановыми значениями и инпутами +/-. Тап «Выполнено» создаёт лог и запускает полноэкранный RestTimer overlay (skip/restart, блокировка прокрутки при активном таймере). Для time-упражнений — Execution Overlay до RestTimer.
- **Аналитика (`/analytics`):** карточки Daily load, top exercises; график Program Trends с режимами неделя/месяц/полгода/год; переключатель детализации по программам/упражнениям. На мобильном график скроллится горизонтально.
- **Ассистент (`/assistant`):** wizard с шагами профиля/целей/ограничений/частоты тренировок → POST `/api/llm-agent/programs/` → показываем созданные программы (одна активна). При ошибке выводим дружелюбный fallback «создание через помощника недоступно…».
- **Профиль/Настройки:** просмотр и редактирование профиля, предпочтений LLM, выход из аккаунта.

## 4. UX/UI требования
- **Общий каркас:** AppHeader/Toolbar с названием и доступом к профилю; унифицированные отступы; OfflineBanner при потере сети.
- **Формы:** кастомные поля с label и ошибками, кнопки с состояниями loading/disabled. Интерактивные элементы должны быть удобны для тача (минимум 44px).
- **Rest Timer:** полноэкранный overlay с анимированным кругом (Reanimated), кнопки skip/restart. Таймер и модалки должны блокировать gestures на подложке, поддерживать работу офлайн.
- **Responsive/адаптации:** оптимизация под телефоны (iPhone 13 mini и выше, Android средний сегмент). Планшеты отображают двухколоночный список (при ширине ≥768).
- **Доступность:** фокус-ловушки для модалок, aria/Accessibility labels, контраст не ниже WCAG AA, поддержку screen reader.

## 5. Состояния, офлайн и ошибки
- **Auth/Session:** токен и user-данные хранятся в AsyncStorage; контекст авторизации оборачивает приложение.
- **Данные:** сетевой слой с `apiFetch`/`fetcher` добавляет токен; кеширование запросов через react-query/SWR-эквивалент. Ошибки показываем через toast/alert.
- **Офлайн-очередь:** логи чеклиста, не отправленные из-за сети, пишутся в локальную очередь (ключ `workout_day/template_exercise/set_index`). При восстановлении связи отправляем автоматически; UI помечает «В очереди» и поясняет, что синхронизация произойдет позже.
- **Редиректы:** при отсутствии токена приватные экраны перебрасывают на `AuthStack`.
- **LLM ошибки:** тайм-аут или неверный JSON от OpenRouter → HTTP 503 и сообщение «создание через помощника недоступно…», логируем на бэкенде, фронт показывает fallback.

## 6. Интеграции и данные
- **API-эндпоинты:** используем те же REST маршруты, что и веб (`/api/auth/login/`, `/api/auth/register/`, `/api/programs/folders/`, `/api/programs/templates/`, `/api/exercises/`, `/api/programs/template-exercises/`, `/api/workouts/plan/`, `/api/workouts/logs/`, `/api/workouts/recommendations/`, `/api/workouts/recommendations/apply/`, `/api/analytics/*`, `/api/llm-agent/programs/`).
- **Каталог упражнений:** отображаем системный список (Exercise_DB) + кастомные пользователя; `has_weight`/`has_time` наследуются от источника, TemplateExercise хранит overrides.
- **Логирование:** приложение отправляет идентификатор пользователя, время, payload/ответ (без PII) для запросов к LLM, чтобы соответствовать бэкенд-логике аудита.

## 7. Нефункциональные требования
- **Поддерживаемые ОС:** iOS 15+, Android 8+. Проверка производительности на mid-range устройствах.
- **Сборка:** React Native CLI (не Expo). Release-сборки с подписью, CI-джобы для `npm run lint`, `npm run test`, `npm run ios --configuration Release`/`npm run android --variant release` (либо gradle assembleRelease).
- **Тесты:** React Native Testing Library + Jest для ключевых экранов (Auth, Onboarding wizard, Checklist, Rest Timer). Снепшоты ограниченно; основные проверки — поведение и состояния.
- **Линт/формат:** ESLint + Prettier (совместимые с фронтом правила). Type-check обязательно.
- **Безопасность:** хранение токена только в AsyncStorage; защищённые скриншоты (Android FLAG_SECURE опционально для чувствительных экранов).
