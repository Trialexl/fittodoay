# fitTODOay — Product Requirements Document (PRD)

## 1. Обзор
- **Миссия:** предоставить пользователю полностью управляемый тренировочный день — от планирования программ до выполнения подходов с таймерами, аналитикой и AI-ассистентом.
- **Ключевые особенности:** мощный редактор программ, каталог упражнений (системные + кастомные), генерация программ через LLM, офлайн-режим для выполнения подходов, визуальная аналитика и рекомендации.
- **Технологический стек:** backend — Django + PostgreSQL, frontend — Next.js (App Router). Документация находится в каталоге `docs/`.

## 2. Цели и KPI
- **Ангажированность:** 60% активных пользователей отмечают хотя бы один чеклист в неделю.
- **Завершённость подходов:** ≥70% начатых тренировок доводятся до последнего упражнения.
- **Надёжность:** 100% подходов фиксируются даже при пропаже интернета (офлайн очередь).
- **AI-метрика:** до 85% сгенерированных программ принимаются пользователями без ручных правок.

## 3. Персоны
1. **Самостоятельный атлет** — готовит программы вручную и ценит контроль за нагрузкой.
2. **Новичок** — запускает ассистента, чтобы быстро получить персональный план и дальше донастраивать.
3. **Энтузиаст/коуч** — создаёт несколько папок под цели, анализирует статистику, вносит корректировки.

## 4. Пользовательский путь
1. **Регистрация и профиль** — пользователь заводит аккаунт, заполняет профиль и предпочтения ассистента.
2. **Создание программ** — вручную через редактор или автоматически через AI («Создать с помощником»).
3. **Повседневное использование** — приложение формирует дневной чеклист; пользователь выполняет подходы, таймеры отдыха и офлайн-очередь обеспечивают непрерывность.
4. **Аналитика** — графики и рекомендации показывают динамику нагрузки, помогают корректировать план.

## 5. Функциональный охват

### 5.1 Аутентификация и профиль
- Вход по email + паролю, сброс пароля через письмо.
- Профиль включает: цель, пол, возраст, вес, рост, уровень подготовки, оборудование, ограничения по здоровью.
- Предпочтения LLM-ассистента (`llm_preferences`) сохранены в профиле и подтягиваются в визарде.

### 5.2 Программы и шаблоны
- **ProgramFolder**: название, комментарий, сортировка, флаг активности. Есть дефолтная папка «Основные».
- **DayTemplate**: принадлежит папке, поддерживает расписания — дни недели, раз в N недель, раз в X дней, список конкретных дат.
- Деактивированные папки/шаблоны визуально помечаются постфиксом «- не активен».
- Drag & drop между папками и сортировка внутри.

### 5.3 Каталог упражнений
- Системный каталог `Exercise_DB` (700+ упражнений, RU/EN названия, мышцы, инструкции, изображения).
- Пользователь может создавать `CustomExercise` с собственными дефолтами.
- `TemplateExercise` хранит ссылку на системное или кастомное упражнение и только override-поля (вес, повторы, подходы, время, отдых, заметка). Флаги `has_weight`/`has_time` наследуются от источника.

### 5.4 AI-ассистент
- Визард «Создать с помощником» (frontend `frontend/src/app/assistant/page.tsx`) собирает данные профиля + предпочтения.
- Backend endpoint `POST /api/llm-agent/programs/` (`backend/workouts/services.py`) передаёт профиль и каталог доступных упражнений в OpenRouter, валидирует JSON-ответ по схеме и создаёт ProgramFolder/DayTemplate/TemplateExercise.
- Одна программа активна по умолчанию; остальные выключены.
- Ошибки (тайм-ауты, неверный ответ) дают пользователю сообщение «создание через помощника недоступно…» + возвращают HTTP 503. Все обращения логируются (payload без PII, статус, длительность) для аудита.

### 5.5 Выполнение тренировок (чеклист)
- Дневной чеклист собирается сервером (`generate_daily_plan`) по активным папкам/шаблонам и кешируется по дате (`WorkoutDay`).
- Каждый сет отображается отдельной карточкой с плановыми значениями (учитывая overrides).
- Отметка подхода открывает форму фиксации факта (повторы/вес или время). После сохранения:
  - лог (`WorkoutSetLog`) записывается на сервер;
  - запускается полноэкранный Rest Timer (с возможностью пропустить или завершить досрочно);
  - чеклист подсвечивает выполненный сет; закрываются упражнения/шаблоны, если все подходы выполнены.
- Для упражнений с таймером используется Execution Overlay (обратный отсчёт до автоматического открытия Rest Timer).

### 5.6 Офлайн-режим
- Любой лог, который не удалось отправить (пропал интернет), добавляется в локальную очередь (`useOfflineWorkoutQueue`, `localStorage`).
- Очередь хранит уникальные комбинации `workout_day/template_exercise/set_index`. При восстановлении сети фоновые попытки (и событие `online`) автоматически отправляют накопленные подходы.
- UI показывает баннер «подходы будут синхронизированы» и помечает такие подходы бейджем «В очереди». Пользователь не теряет прогресс и видит фактические значения до синхронизации.

### 5.7 Аналитика и рекомендации
- Страница аналитики (компоненты `AnalyticsPanels` и `ProgramTrendPanel`) отображает:
  - агрегаты дневной нагрузки (`/api/analytics/days/`);
  - топ упражнений по объёму (`/api/analytics/exercises/`);
  - интерактивные графики Recharts по папкам и упражнениям (режимы line/area/scatter/columns/heatmap/pie; возможность фокусироваться по легенде).
- Блок рекомендаций в чеклисте (`fetchRecommendationsForDay`) показывает предложения по конкретным упражнениям и даёт кнопки для применения (PATCH `TemplateExercise` overrides).

### 5.8 UX и локализация
- Интерфейс на русском языке, мобильная адаптивность (основа в Tailwind CSS + кастомные компоненты).
- Неактивные элементы помечены постфиксом и сниженным контрастом.
- Таймеры и модальные окна доступны с клавиатуры (фокус-ловушки, aria-атрибуты).

### 5.9 Логирование и инфраструктура
- Весь трафик к OpenRouter логируется (ID пользователя, timestamp, sanitized payload, ответ, код).
- Backend хранит историю тренировок, статусы, источники папок/шаблонов.
- В `docs/backendapi.md` описаны актуальные REST эндпоинты.

## 6. Модель данных (упрощённо)
- `User`, `UserProfile`, `llm_preferences`.
- `ProgramFolder`, `DayTemplate`, `TemplateExercise`.
- `Exercise_DB` и связанные `ExerciseMuscle`, `ExerciseInstruction`, `ExerciseImage`; `CustomExercise`.
- `WorkoutDay`, `WorkoutSetLog` (уникальный ключ `(workout_day, template_exercise, set_index)`), `Recommendation`.
- Таблицы аналитики агрегируются on-the-fly (SWR + API).

## 7. UX-экраны
1. **Onboarding профиля и предпочтений ассистента.**
2. **Список программ / ProgramBoard** — управление папками и шаблонами, drag&drop редактор.
3. **Assistant Wizard** — пошаговое общение с LLM и вывод резюме программ.
4. **Workout Checklist** — папки → шаблоны → упражнения → сет, таймеры и офлайн-индикатор.
5. **Analytics** — графики нагрузки, топы упражнений, интерактивная легенда.

## 8. Нефункциональные требования
- **Производительность:** генерация дневного плана ≤1 сек; UI рендерит чеклист до 50 шаблонов без лагов.
- **Надёжность:** офлайн-очередь гарантирует сохранность данных; повторные попытки синхронизации не создают дубликаты.
- **Безопасность:** токены хранятся в `localStorage`, запросы идут по HTTPS, пароли — через Django auth (PBKDF2).
- **Observability:** логирование AI-запросов и критичных операций, метрики ошибок.

## 9. Этапы разработки
1. **MVP (реализован):** программы, чеклист, AI-ассистент, аналитика, офлайн-очередь.
2. **Ближайшие задачи:** ограничения тарифа, персонализация дефолтов, расширение каталога описаний.
3. **Будущее:** экспорт/импорт программ, интеграции носимых устройств, мульти-язычность, социальные логины.
