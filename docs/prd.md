# fitTODOey — Product Requirements Document (PRD)

## 1. Обзор
- **Цель продукта:** помочь пользователям самостоятельно планировать персональные тренировки на неделю и оперативно выполнять их с учётом прогресса и отдыха.
- **Уникальность:** сочетает гибкие шаблоны чеклистов "дел сегодня" с фитнес-нагрузкой, автоматическим таймером отдыха и аналитикой по фактическим сетам.
- **Технический стек:** backend — Django, frontend — Next.js. Вся документация хранится в `docs/`.

## 2. Цели и метрики
- Ежедневная активность: ≥60% авторизованных пользователей отмечают чеклист хотя бы раз в неделю.
- Завершённые тренировки: ≥70% начатых чеклистов доходят до последнего упражнения.
- Качество рекомендаций: ≤15% отклонение между предложенными и фактическими параметрами (по весу/повторам).
- Расширяемость: AI подключается к готовой структуре без изменения схемы данных.

## 3. Персоны
1. **Самостоятельный атлет** — уже знает упражнения, хочет гибко управлять расписанием и отслеживать прогресс.
2. **Новичок** — нуждается в шаблонах и предложениях от AI (из встроенного каталога упражнений).
3. **Коуч/энтузиаст** — создаёт несколько программ (папок) под цели (рельеф, сила, выносливость) и переключает пользователей между ними.

## 4. Основные сценарии
1. Регистрация/email+пароль → заполнение профиля → AI предлагает набор программ (после будущей интеграции) → пользователь активирует нужные папки.
2. Создание программ и шаблонов: выбор дня недели/правил повторения, настройка упражнений из каталога или пользовательских.
3. Ежедневный чеклист: после авторизации приложение автоматически формирует список активных шаблонов на день, пользователь отмечает подходы, система запускает таймер отдыха и сохраняет фактические данные.
4. Аналитика: пользователь видит графики и рекомендации на основании логов выполненных подходов.

## 5. Функциональный охват
### 5.1 Профиль пользователя
- Поля (все обязательные): цель тренинга (пресеты: рельеф/сила/выносливость/гипертрофия), пол, возраст, вес, рост, уровень подготовки, доступное оборудование, ограничения по здоровью.
- После заполнения профиль генерирует промпт для AI (будет активирован после завершения MVP).

### 5.2 Программы и шаблоны
- Папки-программы:
  - По умолчанию создаётся папка «Основные» (активна).
  - Поля: название, комментарий, флаг активности, сортировка.
  - Drag&drop перемещение шаблонов между папками.
  - Деактивированная папка отображается с постфиксом «- не активен» (данные в БД неизменны).
- Шаблон дня тренировки:
  - Привязан к папке и правилу повторения. Поддержать: стандартные дни недели, раз в N недель, раз в X дней, пользовательские исключения.
  - Поля: название, комментарий, активность, расписание.
  - Наследует состояние активности папки (если папка off, шаблон off и отображается с постфиксом).
  - В шаблон добавляются упражнения в порядке выполнения с настройкой параметров (см. 5.3).

### 5.3 Упражнения и параметры
- Каталог по умолчанию хранится в `docs/exercise.csv` (100 популярных упражнений с колонками: `Название, Вес, Время, Количество повторений, Время отдыха между повторениями, Краткое описание, Целевые мышцы`).
- В БД: модель `Exercise` (системные записи) и модель `CustomExercise` (привязана к пользователю, не участвует в AI).
- При добавлении упражнения в шаблон отображаются поля в зависимости от типа:
  - Если упражнение требует веса → поле «Вес» обязательно, иначе скрыто.
  - Если требует время → поле «Время» обязательно, иначе скрыто.
  - Всегда доступны: количество повторений за подход, количество подходов, время отдыха между подходами (дефолт 60 сек), краткое описание.
- Пользователь может расширять каталог индивидуальными упражнениями (собственная модель, видна только владельцу).

### 5.4 Выполнение тренировки
- После авторизации приложение проверяет активные папки/шаблоны и формирует чеклист на текущую дату.
- Если расписаний несколько, первым показывается чеклист из папки «Основные», затем остальные.
- Каждый подход отображается отдельной строкой с параметрами по умолчанию.
- Во время выполнения пользователь может скорректировать вес/повторы/время для конкретного подхода.
- После отметки подхода сохраняется лог: дата (YYYY-MM-DD), пользователь, exercise_id/custom_id, фактические вес/повторы/время.
- Автоматически запускается таймер отдыха на значение из шаблона; таймер должен работать офлайн/при низком интернете (критерии: падение соединения не сбрасывает отсчёт, данные синхронизируются после восстановления).

### 5.5 Аналитика и рекомендации
- Статистика по упражнениям: динамика веса, повторов, времени, объёма по неделям и месяцам.
- AI (этап 2) анализирует логи и предлагает корректировки внутри допустимых диапазонов (например, 8–12 повторов). Пока ограничивается системным каталогом.

### 5.6 Локализация и UI
- MVP поддерживает только русский язык.
- Переключение языков в будущем должно быть учтено в архитектуре (строки выносить в ресурсы).
- Неактивные элементы получают визуальный постфикс «- не активен» и сниженный контраст.

### 5.7 Аутентификация и безопасность
- Единственный способ входа: email + пароль.
- Требуется подтверждение email (ссылка) и политика сложности пароля (не менее 8 символов, цифры + буквы).
- Поддержать сброс пароля через email.

### 5.8 Ограничения
- Нет шаринга программ между пользователями в MVP.
- AI не использует пользовательские упражнения.
- Нельзя выполнять деструктивные операции без подтверждения (например, удаление папки/шаблона требует диалога).

## 6. Модель данных (высокоуровнево)
- `User`: auth, профиль, настройки локализации.
- `UserProfile`: цель, пол, возраст, вес, рост, уровень, оборудование, ограничения, дата последнего обновления.
- `ProgramFolder`: user_id, название, комментарий, активность, сортировка, timestamps.
- `DayTemplate`: folder_id, название, комментарий, активность, правила повторения (enum + параметры), порядок.
- `TemplateExercise`: template_id, exercise_id или custom_exercise_id, порядок, вес, повторы, подходы, время, отдых, заметка.
- `Exercise`: системный справочник (данные из `exercise.csv`), флаги `has_weight`, `has_time`, `default_rest`, `target_muscle_groups`.
- `CustomExercise`: user_id, название, описание, флаги `has_weight`/`has_time`, целевые мышцы.
- `WorkoutDay`: user_id, дата, статус, список активных шаблонов.
- `WorkoutSetLog`: workout_day_id, template_exercise_id, фактические вес/повторы/время, timestamp.

## 7. UX и экраны
1. **Onboarding профиля** — форма с прогресс-баром (поля профиля + оборудование).
2. **Список программ** — папки с drag&drop, тумблер активности, быстрый доступ к шаблонам.
3. **Редактор шаблона** — расписание повторов, список упражнений, модальные окна выбора из каталога / добавления кастомных.
4. **Дневной чеклист** — grouped view по папкам, выполнение подходов, таймер отдыха, офлайн-индикатор.
5. **История/аналитика** — графики по упражнениям, рекомендации (позднее).

## 8. Нефункциональные требования
- **Производительность:** формирование дневного чеклиста ≤1 сек для 50 шаблонов; таймер работает без дрожи ±1 сек.
- **Надёжность:** офлайн запись подхода кэшируется локально и синхронизируется при появлении сети.
- **Безопасность:** защита персональных данных профиля, шифрование паролей (bcrypt/argon2).
- **Масштабируемость:** структура API позволяет подключить мобильное приложение без изменений в модели.

## 9. Зависимости и этапы
1. MVP без AI: профиль, программы, шаблоны, выполнение, логирование, базовая аналитика.
2. AI-рекомендации на основе системного каталога (последний этап).
3. Расширение локализации, социальный логин, шаринг программ (пост-MVP).
