# fitTODOay — Frontend PRD

## 1. Обзор
- **Цель:** реализовать SPA/SSR-клиент на Next.js 14 (App Router), который покрывает все пользовательские сценарии PRD: онбординг профиля, управление программами/шаблонами, выполнение тренировок с таймером отдыха, аналитика прогресса и подготовка данных для AI.
- **Стек:** Next.js 14, React 18, TypeScript, SWR, react-hook-form, Zustand (при необходимости локального состояния), Tailwind/utility‑классы (пока кастомные стили через CSS).
- **API:** REST endpoints Django (`/api/...`). Базовый URL задаётся переменной `NEXT_PUBLIC_API_URL`.

## 2. Пользовательские сценарии
1. **Landing + Auth:** краткое описание продукта, ссылки на вход/онбординг. Страница `login` авторизует пользователя (Token auth). Неавторизованных редиректить на `login`, если они открывают закрытые страницы.
2. **Многошаговый онбординг (`/onboarding`):** регистрация + заполнение всех обязательных полей профиля. После успешного запроса пользователь попадает на страницу программ.
3. **Программы (`/programs`):**
   - Список папок с возможностью включить/выключить и добавить новую.
   - Редактор шаблонов: выбор папки, расписания, формы добавления упражнений (системное или кастомное), настройки override-полей.
4. **Чеклист (`/workout`):**
   - Загрузка плана (`/api/workouts/plan/`), отображение списком папок → шаблонов → упражнений.
   - Каждому сету соответствует отдельная строка с кнопкой «Выполнено». По нажатию отправляется лог (`/api/workouts/logs/`) и запускается полноэкранный таймер отдыха.
   - Таймер должен работать офлайн, иметь кнопки skip/restart и блокировать прокрутку при активном состоянии. Для полей повторы/вес/время используются инпуты с кнопками +/- (поддержка долгого нажатия, шаги 1/2/1 сек).
   - После завершения программы пользователь видит блок с рекомендациями (по каждой папке отдельно): отображаются фактические средние значения, предложенные корректировки и кнопка «Применить» (патчит TemplateExercise через `/api/workouts/recommendations/apply/`). При открытии блока «Рекомендации» папка автоматически раскрывается, а первое поле получает фокус.
5. **Аналитика (`/analytics`):** 
   - карточки ежедневной нагрузки и топ-упражнений (как базовая сводка),
   - дополнительный график «Динамика по программам» со свитчером периодов (неделя/месяц/полгода/год) и детализациями «по программам»/«по упражнениям». В мобильном варианте график отображается как прокручиваемые столбцы. Источник данных — `/api/analytics/program-trends/?range=…&granularity=day|week`.
   - блок AI-рекомендаций (placeholder до интеграции).

## 4. Требования к UX/UI
- **Глобальный layout:** AppHeader (название, ссылки `Программы / Чеклист / Аналитика`, состояние пользователя + кнопка «Выйти»), OfflineBanner, единые отступы (px-4 pt-20).
- **Формы:** кастомные инпуты с label и ошибками; кнопки с состоянием loading/disabled.
- **Онбординг:** прогресс по шагам, сохранение данных в локальном состоянии до финального submit.
- **Template Editor:** модульные карточки упражнений, переключатели для расписания (weekly, biweekly, interval, custom). Необходимо предусмотреть табы «Каталог/Мои упражнения» в будущем (сейчас список общих).
- **Чеклист:** отдельные карточки упражнений, визуальное разделение сетов, статус «Не активен» наследуется.
- **RestTimer:** полноэкранный overlay, анимированный круг прогресса, кнопка пропуска/повтора. При офлайне отображать бейдж «Нет соединения».
- **Responsive:** минимум планшетная поддержка (768px) + десктоп. Мобильный режим допустим упрощённый (стек карточек).

## 5. Состояния и ошибки
- **AuthContext:** хранит user/token в localStorage, оборачивает app.
- **SWR:** базовый fetcher использует `apiFetch`, добавляет токен; необходимо обрабатывать ошибки (toast/alert).
- **Offline:** `useOffline` показывает баннер и при отправке логов в офлайне нужно информировать пользователя, что чеклист синхронизируется после восстановления (логирование планируется через локальные очереди).
- **Редиректы:** если нет токена, страницы `/programs`, `/workout`, `/analytics` должны перенаправлять на `/login`.

## 6. Нефункциональные
- **Сборка:** `npm run build` должен проходить (Next.js SSR + types), Dockerfile для фронта строит прод-образ (`frontend/Dockerfile`).
- **Тесты:** минимум unit тесты для ключевых компонентов (кнопка, онбординг, чеклист) на React Testing Library + Jest (`npm run test`).
- **Линт:** `npm run lint` обязательный шаг CI.
- **Конфигурация:** `.env.local` с `NEXT_PUBLIC_API_URL`, в проде задаётся через переменные Docker.

## 7. Бэклог
- Drag&drop шаблонов и упражнений (UI + API).
- Тема (dark/light), кастомные палитры Tailwind.
- PWA/offline storage для логов (IndexedDB), синхронизация после reconnect.
- Playwright end-to-end сценарии.

## 8. Вторая версия дизайна (04.11.2026)

V1 остаётся вариантом по умолчанию. V2 охватывает вход, онбординг, тренировку,
программы и редакторы, аналитику, помощника, проверку техники и общие диалоги.
Бизнес-сценарии записи подходов, таймеров и сохранения программы одинаковы.

Контракт: `UserProfile.llm_preferences.design_version` →
`LLMPreferencesSerializer` / `GET, PUT /api/profile/preferences/` → `ThemeProvider` →
`html[data-design="v1"|"v2"]`. Допустимы только `v1` и `v2`, по умолчанию `v1`.
Используется существующее JSON-поле, новая миграция не нужна. Частичное обновление
не удаляет настройки анкеты; запись сериализуется транзакцией с блокировкой профиля.

Переключатель находится в меню «Оформление» рядом с темой и акцентным цветом.
Изменение применяется без навигации и повторного монтирования страницы: незавершённый
ввод и состояние таймера сохраняются. Для авторизованных выбор хранится в профиле,
для гостей — на устройстве. Кеш разделён по аккаунтам, при входе сервер имеет приоритет.
При ошибке сохранения видны пояснение и кнопка повторного сохранения.

V2: контрастная боковая навигация от 1100 px, нижняя — на меньших экранах.
Отдельная компоновка тренировки и каталога программ; Grid с minmax(0, 1fr),
адаптивные строки подходов и перенос длинных названий без фиксированной высоты текста.
Светлая/тёмная темы и произвольный акцент поддерживаются в обеих версиях.
Крупные сенсорные цели, видимый фокус, переход к содержимому, ограничение фокуса
в диалогах, Escape и возврат фокуса; уменьшенная анимация через prefers-reduced-motion.
Нижняя навигация и музыкальный плеер имеют отдельные области с учётом safe area.

Дизайн изолирован в `design-v2.css`. V2 использует отдельные компоненты
`WorkoutOverview`, `ModernExerciseHeading`, `ModernSetRow`, `ProgramNavigator`;
логика записи подходов, таймера, измерений, редактирования и API остаётся общей.
Общих правил `font: inherit`, увеличивающих все кнопки/поля, нет: размеры контролов
задаются компонентами, подписи и длинные названия переносятся.
Разработка и сборка используют закреплённый Next.js 15.5.21.

Проверки: backend `pytest accounts`, frontend `npm run lint`, `npm test`, `npx tsc --noEmit`,
`npm run build`. DOM-тесты проверяют обе стороны переключения, сохранение ввода,
ошибки/повтор, последовательные запросы и изоляцию аккаунтов.
Ручная проверка компоновки в настоящем браузере обязательна до развёртывания.

Переработка после визуальной обратной связи (04.11.2026):

### Экран таймера V2

Общий `WorkoutTimerScreen` отображает отдых и выполнение: тёмный фон, крупные
цифры m:ss, убывающее кольцо оставшегося времени с делениями. Отдых
использует акцент профиля, выполнение — светлый зелёный акцент. Новых действий
паузы или изменения длительности не добавляется; используются существующие
обработчики завершения, отмены и фактических значений подхода.

На десктопе отсчёт слева, упражнение/результат/действия справа. На телефоне
вертикальная компоновка; на коротком горизонтальном экране обе колонки и основные
кнопки помещаются в высоту. Допускается внутренняя прокрутка при увеличенном тексте.
Свёрнутая панель показывает оставшееся время, упражнение и действия раскрытия/закрытия.
Редактируемые поля и отсчёт сохраняются при сворачивании. Фокус ограничен экраном,
Escape вызывает прежний обработчик закрытия; уменьшенная анимация поддерживается.
