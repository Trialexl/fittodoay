# fitTODOay Android

Нативный Android-клиент на Kotlin / Jetpack Compose, отдельный от `frontend`.
Основа переноса: `origin/main` на `c8a2d05` (получен 19 ноября 2026).
Сервер: **https://trialexl4.freemyip.com/**. WebView не используется.

## Разработка

Общая ветка разработки — `main`: backend, веб и Android обновляются вместе из одного репозитория.
Android остаётся отдельным клиентом в каталоге `android-native` и использует общий backend API.
По решению пользователя незавершённые версии не публикуются даже как prerelease.
Промежуточные APK и галереи остаются локальными. Публикация — после завершения
сверки приложения с вебом и проверки пользовательских сценариев.

Текущая локальная итерация `0.4.3-dev`: плейлист Material 3, календарь
Kizitonwose, видео Media3 и стандартные поля/индикаторы. Проверки и ограничения —
[COMPONENTS_REVIEW.md](COMPONENTS_REVIEW.md). Выбор компонентов — [UI_COMPONENTS.md](UI_COMPONENTS.md).
Предыдущая итерация `0.4.2-dev`: графики Vico/KoalaPlot, галерея Compose Pager
и приглушение музыки при сигнале таймера — [LIBRARY_REVIEW.md](LIBRARY_REVIEW.md).
Предыдущая локальная итерация с компактным чеклистом и управлением плейлистом:
[DENSITY_REVIEW.md](DENSITY_REVIEW.md).

Предыдущая переработка плейлиста, виджетов, информации об упражнениях и диаграмм в 0.4.0:
[DESIGN_REVIEW.md](DESIGN_REVIEW.md). Проверки и ограничения сборки:
[RELEASE_CHECKS.md](RELEASE_CHECKS.md).

JDK 17, Android SDK 35, build-tools 35.0.0, Gradle 8.11.1.
Минимальная версия устройства: Android 8 (API 26).

На этом компьютере инструменты установлены для пользователя Alex:

- JDK: `%LOCALAPPDATA%/Programs/Java/`;
- Gradle: `%LOCALAPPDATA%/Programs/Gradle/gradle-8.11.1/`;
- Android SDK и эмулятор: `%LOCALAPPDATA%/Android/Sdk/`;
- виртуальное устройство: `%USERPROFILE%/.android/avd/`.

`JAVA_HOME`, `ANDROID_HOME` и пути Android CLI добавлены в пользовательское окружение.
Новый терминал подхватит их автоматически.

```powershell
cd C:\git\fittodoay\android-native
./tools/android.ps1 doctor
./tools/android.ps1 build
./tools/android.ps1 emulator
./tools/android.ps1 install
./tools/android.ps1 test
./tools/android.ps1 full-test
./tools/android.ps1 lifecycle-test
./tools/android.ps1 layout-test
./tools/android.ps1 visual-test
./tools/android.ps1 visual-snapshot
./tools/android.ps1 workout-test
./tools/android.ps1 workout-test -VisualLayout tablet
```

`test` сохраняет установленное приложение и его сессию. Проверка формы входа выполняется только
на устройстве без авторизации; она не выходит из существующего аккаунта и не стирает данные.

Проверка с реальным сервером включается отдельно:

```powershell
./tools/android.ps1 live-test
```

Она создаёт синтетический QA-аккаунт, если устройство не авторизовано, либо повторно использует
ранее созданный QA-аккаунт с проверкой привязки к сессии. При обычном пользовательском входе
тест останавливается до изменения данных. Проверяются серверные записи, нативные экраны и AI-чат.
Пароль и токен не печатаются в отчёте. Снимки и отчёт создаются в приватном каталоге
приложения `files/qa-artifacts/`; копия последнего успешного прогона — `artifacts/live/`.

Обычные команды Gradle также доступны:

```powershell
./gradlew.bat assembleDebug
./gradlew.bat testDebugUnitTest lintDebug
./gradlew.bat connectedDebugAndroidTest
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.
Отчёты: `app/build/reports/`.
Debug APK предназначен для разработки; release-подпись и публикация отдельно.

## Сеть при первоначальной установке

На этом компьютере наблюдались прерывания TLS при загрузке зависимостей Java.
`tools/download.mjs` скачивает официальные файлы по HTTPS с проверкой сертификатов и повторными попытками.
Для Gradle есть необязательный локальный кэш `tools/maven-cache.mjs`: он слушает только `127.0.0.1:18765`,
получает артефакты с Google Maven и Maven Central по HTTPS и сохраняет их в `%LOCALAPPDATA%/fitTODOay/maven-cache/`.
В проекте остаются стандартные официальные Maven-репозитории; обходная конфигурация применяется только через внешний init-скрипт.

Windows на этом компьютере использует локальный HTTP-прокси `127.0.0.1:12334`.
Эмулятор настроен на тот же прокси через адрес хоста `10.0.2.2:12334`.
Этот адрес не зашит в APK: приложение использует сетевые настройки Android.
Для тестового AVD отключено обнаружение captive portal (`captive_portal_mode=0`):
через этот VPN системная проверка Google приводила к отключению AndroidWifi.
Это настройка только эмулятора; HTTPS приложения продолжает проверять сертификаты.
Исходное значение сохранено вне репозитория; вернуть стандартное поведение можно
командой `adb shell settings delete global captive_portal_mode`.
После настройки отдельный диагностический прогон дал 8 успешных соединений TLS
1.3 / TLS 1.2 с проверкой сертификатов. В длинных прогонах остаются обрывы Wi-Fi
эмулятора и сетевые тайм-ауты; диагностика не означает стабильный end-to-end паритет.
Перед сетевыми тестами скрипт явно подключает тестовый AVD к AndroidWifi.

## Данные и безопасность

- Тот же Django REST API и `Authorization: Token`, что в веб-клиенте.
- Токен зашифрован ключом Android Keystore. Пароль не сохраняется; backup приложения отключён.
- LLM и OpenRouter остаются на backend. В APK нет ключей LLM.
- Запросы API не следуют перенаправлениям с токеном.
- Подходы и вес тела сохраняются в локальную очередь при сетевой ошибке.
- Очередь и кэш плана разделены по аккаунтам; при синхронизации проверяется существующий подход,
  чтобы повтор после потерянного ответа не создавал дубль.
- Загрузка видео/MP3 идёт потоково из временного файла с ограничением размера.

## Готовность

Нативная реализация работает на указанном сервере; **полный паритет ещё не подтверждён**.
Список сценариев и фактические результаты проверки: [PARITY.md](PARITY.md).

Визуальная сверка: [VISUAL_REVIEW.md](VISUAL_REVIEW.md).
`visual-test` использует живой сервер; `visual-snapshot` требует заранее записанные
ответы синтетического аккаунта в `%LOCALAPPDATA%/fitTODOay/visual-snapshot/reference.json`
и проверяет отрисовку с выключенной сетью.

## Подписанный APK

Сборка APK-кандидата после прогона проверок: `./tools/build-release.ps1`.
Ключ подписи хранится в `%LOCALAPPDATA%/fitTODOay/android-signing/`, пароль защищён
Windows DPAPI для текущего пользователя. Эти файлы находятся вне репозитория.
Скрипт проверяет подпись, отсутствие debug-режима и создаёт APK, SHA256SUMS.txt и
публичный сертификат в `artifacts/release/`. Загрузка в GitHub выполняется отдельно
после проверки результатов; сборка сама ничего не публикует.
Неуспешные обязательные проверки блокируют публикацию готового релиза.
`./tools/smoke-release.ps1` проверяет установку точного подписанного APK и первый
запуск на отдельном AVD `fitTODOay_Release_API_35`, затем возвращает исходный QA AVD.
Он не проверяет закрытые серверные сценарии и не удаляет данные исходного приложения.

## Локальное хранение (0.2.0)

Данные разделов, каталог и изображения, история, переписка и результаты техники
сохраняются на устройстве для просмотра без интернета. Музыкальные файлы остаются
потоковыми. Первая полная загрузка выполняется при подключении и продолжается
после перезапуска. Её статус находится в профиле, в блоке «Данные на устройстве».

Создание и редактирование программ и профиля остаются через сервер; офлайн-очередь
подходов и веса сохранена. Подробности, ограничения API и проверки: [LOCAL_DATA.md](LOCAL_DATA.md).
