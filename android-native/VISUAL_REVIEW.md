# Доработка нативного интерфейса · 20.11.2026

Стек сохранён: Kotlin, Jetpack Compose, Material 3. В этой итерации версии
зависимостей не менялись. Веб-эталоны шести разделов находятся в
`artifacts/ui-v4/web/`, галерея — `artifacts/ui-v4/comparison.html`.

Изменения:

- Единая читаемая типографика, поля OutlinedTextField с постоянными подписями,
  увеличенные кнопки, навигация и действия в программах.
- Нижняя навигация на телефоне; NavigationRail для ширины от 840 dp.
  Плеер сохраняется снизу с системными отступами.
- Прокрутка разделов, выбранная программа, раскрытие дней и шаг анкеты
  восстанавливаются при переключении вкладок. Состояние разделено по сессиям.
  Системная кнопка «Назад» возвращает из раздела к тренировке.
- В программе показаны реальные цели и отдых: override → значение каталога →
  существующий default редактора. Временные упражнения показывают секунды,
  упражнения без веса не получают выдуманный вес; нулевые значения сохраняются.
  Также видны заметки и отключённые упражнения.
- Сводка аналитики адаптируется к узкому экрану и увеличенному шрифту.
  Длинная подпись четвёртого шага анкеты сокращена до «Пожелания».

Контракт использует существующий API программ и вложенные exercise/custom_exercise;
изменения схемы БД, миграции и серверное развёртывание не требуются.

Проверки: 40 JVM-тестов (включая 4 новых регресса параметров упражнений),
Android Lint — 0 ошибок, 27 предупреждений. Визуальная проверка выполняется
на сохранённых ответах API синтетического аккаунта с отключённой сетью:
6 разделов в светлой/тёмной теме, четыре шага анкеты, сохранение шага при
переходе между разделами, параметры программы, редактор подхода без применения,
календарь и диалог оформления. Размеры: 360, 393 и 1067 dp — все три прогона успешны.

Дополнительно `local-data-test` прошёл: 5 проверок SQLite/архивного видео,
подготовка офлайн-аккаунта, проверка всех шести разделов, чата, черновика и видео
после реального завершения процесса, восстановление исходной QA-сессии.
Отчёты: `artifacts/local-data-store.txt`, `local-data-prepare.txt`,
`local-data-verify.txt`, `local-data-restore.txt`.

Ограничения: визуальные снимки не проверяют серверные записи, реальный AI,

# Визуальная сверка с веб-версией

Веб-эталон — https://trialexl4.freemyip.com/, отдельный синтетический аккаунт.
Сняты чеклист, программы, аналитика, техника, помощник и оформление.

## Что перенесено

- Нейтральный фон, белые карточки с тонкими границами, размеры текста и отступы.
- Компактная шапка; пять разделов в нижней навигации V2 и профиль сверху.
- Тёмная сводка тренировки V2: реальное выполнение подходов, нагрузка и мышцы.
- Компактные подходы; параметры раскрываются по кнопке редактирования.
- Выбор программы V2 и свёрнутые папки V1. Новая программа выбирается автоматически.
- Заголовки по веб-образцу, карточки выбора оформления и цветовая палитра.
- Постоянный нижний плеер с перемоткой, очередью и случайным порядком.

## Проверка

`./tools/android.ps1 visual-snapshot` снимает 6 разделов V2 и все 4 шага анкеты при ширине
393 dp. Активный объём — только V2. Он использует сохранённые реальные ответы 11 API тестового аккаунта,
с сетью эмулятора, выключенной на время снимков. Серверные записи этим тестом не
создаются. После проверки сеть и размеры восстанавливаются.

Проверяется также, что открытие редактора и изменение поля веса подхода не изменяет
план до подтверждения. Системные ANR-окна делают проверку снимка неуспешной.
Отдельно проверяется, что плеер и нижняя навигация находятся выше системной полосы
жестов Android. Снимок ожидает готового кадра через
[FrameCommitCallback](https://developer.android.com/reference/android/view/ViewTreeObserver#registerFrameCommitCallback(java.lang.Runnable)).

Этот тест проверяет отрисовку и локальное состояние, **не заменяет сетевой end-to-end
прогон**. Результаты функциональных проверок — в [PARITY.md](PARITY.md).
Совпадение каждого пикселя не заявляется: это отдельный нативный интерфейс.
