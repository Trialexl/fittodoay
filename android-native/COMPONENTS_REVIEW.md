# Плейлист и стандартные компоненты — 0.4.3-dev

Работа в `main`, без публикации релиза. Backend и API-контракты не меняются.
Матрица выбранных библиотек: [UI_COMPONENTS.md](UI_COMPONENTS.md).

## Изменения

- Плейлист: Material 3 ListItem вместо отдельных рамок треков, DockedSearchBar,
  SecondaryTabRow, DropdownMenu. Поиск, источник и группировка остаются связаны
  с настоящим каталогом; группировка сохраняется через существующий API.
- Выбранная запись очереди определяется индексом: одинаковые треки в разных
  позициях не подсвечиваются одновременно. Сохраняются «следующим», добавление,
  перемещение, удаление и очистка очереди.
- Общий MusicSeekBar использует SliderDefaults.Track/Thumb. Пустое нажатие
  без изменения величины не отправляет нулевую позицию. При буферизации кнопка
  показывает загрузку; пауза доступна и в этом состоянии. Мини-плеер не выводит
  пустую шкалу времени до получения длительности.
- Календарь: Kizitonwose Calendar Compose 2.7.0, свайпы и переходы по месяцам,
  нагрузка из `/api/analytics/days/`, выбор даты и возврат к сегодняшней.
  Неудача загрузки показывается с повтором. MIT-лицензия включена в APK.
- Видео техники: Media3 PlayerView вместо VideoView, штатные контролы,
  загрузка/ошибки, освобождение декодера при уходе в фон, восстановление позиции
  и кадра на паузе при возврате, освобождение проигрывателя при закрытии.
- Вес: OutlinedTextField с единицей измерения и существующим сохранением.
  Мышечные полосы: LinearProgressIndicator. Вкладки/режимы: TabRow,
  SegmentedButton и FilterChip. Кольцо таймера: CircularProgressIndicator;
  Canvas оставлен только для декоративных делений веб V2.

## Границы проверки

Сетевой профильный прогон — 5/5: загрузка из общего плейлиста, очередь/перемотка/
фоновая музыка, фильтры/группировка, календарь и локальные видеоконтролы.
Музыкальный сценарий отдельно прошёл при шрифте 130%, с настоящей клавиатурой
Android: транспорт и минимум 72 dp списка остаются видимыми.
Frontend lint: без ошибок и предупреждений; код frontend не менялся.

Новое поле веса проверено через реальное офлайн-редактирование, пересоздание
Activity, синхронизацию и проверку одной записи в API; исходное значение QA
восстановлено. Media3 проверен на паузу/продолжение и сохранение паузы после
возврата из фона, с ожиданием фактического кадра перед снимком.

Тренировочный регресс — 4/4: длинный чеклист, вложенное сворачивание,
выполнение/отдых, истечение времени, восстановление и редактирование результата.
Кольцо стандартного индикатора просмотрено на открытых экранах выполнения и отдыха.

Заключительный профильный повтор — 3/3 при шрифте 130%: весь музыкальный
сценарий, офлайн-вес и Media3 с видимым кадром после возврата. Название очереди
проверяется по всем 11 отображаемым символам и фактическим границам текста.
Проверка MediaComponentsTest включена в `tools/android.ps1 full-test`.

Визуальная матрица — четыре успешных прогона: 360/393 dp, планшет 1067 dp
и телефон со шрифтом 130%; обе темы, открытые панели, семь видов графиков,
выбор точки, анимация и свайпы галереи. Снимки и отчёты:
`artifacts/components-review/index.html` (89 PNG).

JVM debug/release: по 56/56, без пропусков. Android lint: 0 ошибок,
29 предупреждений (28 прежних и рекомендация обновить новый `media3-ui`).
Совместимая версия Media3 закреплена одинаково для всех его модулей.

Подписанный APK `0.4.3-dev`, code 9, установлен на отдельный AVD. Нативная
авторизация запускается, WebView и debug отсутствуют, hash установленного файла
совпал. Этот smoke не проверяет авторизованные серверные сценарии release.
Файл: `artifacts/working/fitTODOay-0.4.3-dev.apk`; контрольная сумма —
[RELEASE_CHECKS.md](RELEASE_CHECKS.md).

Сетевые сценарии выполняются на отдельном эмуляторе и синтетическом QA-аккаунте.
Загруженные тестовые MP3 удаляются в `finally`. Видео — локальный синтетический
клип. Визуальная матрица использует сохранённые ответы QA и отдельные тестовые
серии графиков; это не результаты пользователя.

При проверке повторной перемотки обнаружена длительная буферизация сервера:
позиция уже менялась, но `isPlaying` оставался false до загрузки. Для неё добавлено
видимое состояние, а тест ожидает реального продолжения воспроизведения до 60 с,
проверяя отсутствие ошибки. Это не обещание устранения сетевой задержки.

Для видео используется [официальный жизненный цикл Media3](https://developer.android.com/media/implement/playback-app):
подготовка при старте Activity и освобождение при остановке. Проверка возврата
дополнительно анализирует область настоящего кадра вне контролов, чтобы чёрная
поверхность с работающей кнопкой не считалась восстановленным видео.

Полная сверка всех функций приложения с вебом и проверка физического телефона
остаются незавершёнными. Эта итерация не объявляет полный паритет и не публикует
незавершённую версию.
