Прежние функциональные проверки не подтверждали сходство самих таймеров и
редактора. После повторного просмотра мобильного веба при 393 × 786 и полного
чтения `timer-v2.css`, `design-v2.css`, `WorkoutTimerScreen.tsx`,
`ExecutionTimerOverlay.tsx`, `RestTimerOverlay.tsx`, `Modal.tsx` и
`AdjustNumberControl.tsx` переработаны следующие детали:

| Выполнение | Зелёный #a9e7c7, кнопки завершения/прерывания в одной строке |
| Отдых | Акцент профиля, фаза «Восстановление», номер подхода рядом |

Окно правки хранит собственный черновик: при вводе строка результата не меняется.
Ошибка не закрывает окно. Для удаления серверного факта требуется интернет;
отмена локальной правки серверного подхода больше не выдаётся за удаление факта.

Новая галерея: `artifacts/v2-correction/index.html`. Предыдущие снимки из
`artifacts/workout-flow/` являются историческими до этого визуального исправления.
Телефонный прогон включает отдельный регресс модального редактора:
открытие из выполненной строки, ввод без изменения факта, закрытие с отменой,
изменение +/−, сохранение без нового таймера, ошибка чисел и отмена выполнения.
Для таймеров дополнительно проверяется мобильный порядок: название выше времени.

На 393 dp и на 1067 dp прошли по 3 UI-сценария; JVM — 46/46, Android Lint —
0 ошибок и 28 предупреждений. Живой серверный прогон — 2/2: время 5 секунд без скрытого веса/повторов;
для силового подхода отмена ввода сохранила исходный факт, PATCH обновил тот же
ID до 12 повторов × 8.5 кг, «Отменить выполнение» удалило этот лог.
Общий VisualSnapshotTest — 1/1, включая открытие/отмену нового окна правки,
календарь, шесть разделов и обе темы. Физический телефон не проверялся.

## Контракт и границы

Существующий API `/api/workouts/logs/`: `workout_day`, `template_exercise`,
`set_index`, `actual_reps`, `actual_weight`, `actual_time`. Новая схема БД не нужна.
Черновик отдыха сохраняется в приватном TimerStore; AlarmManager отвечает за
сигнал, а запись проходит через прежнюю очередь и API. Смена просматриваемой даты
не переназначает результат другой тренировке. Истечение в свернутом виде проходит
через тот же обработчик; ошибка записи не стирает черновик.

Досрочное время округляется вверх до целой секунды (минимум 1, максимум план),
так как существующий контракт положительного времени не допускает 0.

## Проверки

Команда: `./tools/android.ps1 workout-test`. Используется отдельная случайная
синтетическая локальная сессия, Wi-Fi и мобильная сеть отключены; серверные записи
не создаются. Данные 12 упражнений расширены специально для длинного списка на
основе сохранённого ответа каталога; это тестовые данные, а не реальная тренировка.
После проверки исходная зашифрованная QA-сессия и сеть восстанавливаются.

`WorkoutTimerContractTest` проверяет выбор отдыха, последний подход, отключённые
упражнения, уже выполненные подходы и расчёт фактического времени.
`WorkoutFlowTest` проверяет прокрутку, сворачивание, отмену, изменение факта,
восстановление нового ViewModel, ошибки, нулевой отдых, истечение выполнения и
ровно одну запись в постоянной очереди. Это не эквивалент реального завершения
процесса; старый lifecycle-прогон отдельно проверяет системный сигнал.

## Что не объявляется завершённым

Это проверка основного сценария чеклиста, а не полный паритет приложения.
Редактирование программы/дня/упражнения точным переходом из чеклиста, все ветки
чата после тренировки и полный общий сетевой прогон не проверены этой серией.
Текущая проверка восстановления черновика создаёт новый Activity/ViewModel;
новый отдельный прогон с настоящим завершением процесса именно с формой отдыха
не выполнялся. Проверка физического телефона и публикация релиза не выполнялись.

Серверные и frontend-файлы в этой итерации не менялись; миграция и развёртывание
сервера не нужны для описанного сценария. Отладочный APK:
`app/build/outputs/apk/debug/app-debug.apk`.
