# Сверка данных с вебом и локальная история — 0.4.7-dev

Работа в `main`. По прямому запросу пользователя 22 ноября 2026 опубликован
[предварительный релиз 0.4.7-dev](https://github.com/Trialexl/fittodoay/releases/tag/android-v0.4.7-dev).
Публикация следующих сборок автоматически не запускается.

## Найденные расхождения и изменения

| Сценарий | Что обнаружено | Результат |
|---|---|---|
| Открыть календарь повторно | Android очищал значения и ожидал HTTP, хотя история уже сохранена. В вебе данные календаря находятся в SWR до открытия окна | Сначала показываются сохранённые данные, затем идёт запрос обновления |
| Изменить или отменить подход без сети | Чеклист обновлялся из Room, календарь читал отдельный серверный агрегат | Календарь наблюдает историю Room через Flow и учитывает локальные подходы, включая отмену последнего подхода |
| Поздний ответ после изменения | Время сохранения HTTP-ответа могло сделать устаревшие данные новее локального результата | У ответа сохраняется время начала запроса. Более старый ответ не перезаписывает более свежую копию; календарь сопоставляет время ответа и локального плана |
| Старое взвешивание после нового | Локальное изменение добавлялось в конец списка и могло стать «последним весом» | Даты сортируются; локальные записи фильтруются по выбранному периоду, включая его границы |
| Выбрать другой период во время загрузки | Нажатие молча игнорировалось | Старый запрос отменяется, новый период применяется сразу. Поздний результат не заменяет новый выбор |
| Открыть тренировку из аналитики | После замены карточек дней графиком пропал переход, который есть в вебе | После выбора даты на графике нагрузки доступно «Открыть тренировку» |
| Календарная сетка | В вебе 42 ячейки и отдельное выделение сегодняшнего дня | `OutDateStyle.EndOfGrid` библиотеки Kizitonwose, шесть недель, отдельная рамка сегодняшней даты. Высота ячеек учитывает шрифт; содержимое прокручивается на узких экранах |
| Отключённые анимации | В общем UI-прогоне Vico мог остаться на начальном placeholder | При нулевом `MotionDurationScale` библиотеке передаётся `animationSpec=null`; при обычных настройках остаётся анимация 700 ms |
| Форма Play | По замечанию пользователя круглая кнопка заменена овальной | Штатный Material 3 `FilledTonalIconButton`: 56×40 dp в мини-плеере, 64×44 dp в плейлисте, скругление 50% |
| Сводка тренировки при шрифте 130% | Подписи трёх счётчиков слипались | Три колонки одинаковой ширины с отступами и переносом текста; добавлен промежуток до кольца прогресса |

Формула локальной нагрузки соответствует существующему `workoutLoad` и серверному
контракту: вес × повторы, повторы без веса, либо секунды / 10; затем плановые
значения для старых записей без фактических параметров. Неизвестный день обозначен
точкой, известный нулевой результат — тире. Отсутствующие данные не выдаются за
выполненную или пустую тренировку.

## Хранение и API

Room: версия схемы 2 → 3, поле `workout_plans.updatedAt` с исходным значением 0.
Используется AutoMigration; планы, очередь и черновики не сбрасываются. Схемы
предыдущих версий сохранены. Сохранённый серверный план передаёт своё исходное
время в Room, чтобы чтение старой копии не делало её новой.

В существующей таблице ответов SQLite уже есть `updated`: оно используется как
время начала запроса. Для диапазонов дней/веса выбирается более свежая из точной
копии диапазона и полной локальной истории. Данные и время читаются вместе.

Файловые/SQLite операции и преобразование истории выполняются вне UI-потока.
Room владеет транзакциями и уведомлениями об изменении; WorkManager и очередь
отправки остаются прежними. Серверные модели, endpoint и миграции backend не менялись.

## Проверки

Регрессии включают поздний HTTP-ответ после уже подтверждённой записи, отмену
последнего подхода без сети, закрытие/открытие календаря, переключение периода
во время HTTP, открытие тренировки из графика, границы периода взвешиваний и
миграцию существующей базы версии 2 с индексами, очередью и черновиками.

Итоговые количества, галерея и подписанный APK фиксируются в
[RELEASE_CHECKS.md](RELEASE_CHECKS.md) после проверки сборки.

## Ограничения

Без сети доступны только ранее сохранённые данные. Полная загрузка архива и
синхронизация другого устройства требуют соединения. Программные тренды и
рейтинг упражнений используют серверные агрегаты; локальный пересчёт этих
агрегатов для ещё не отправленных подходов в этой итерации не добавлен.

Полная сверка всех экранов веба и проверка физического телефона не завершены.
Проверки эмулятора с программным GPU не подтверждают производительность 60 fps.
