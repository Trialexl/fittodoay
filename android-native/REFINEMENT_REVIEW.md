# Черновики, фоновые задачи и визуальная плотность — 0.4.5-dev

Работа в `main`. Backend и API не меняются. Сборка остаётся локальной.

## Что изменено

| Подтверждённая проблема | Используемое решение | Результат |
|---|---|---|
| Черновик чата и анкета обращались к SQLite из UI | Room, Flow.debounce, Dispatchers.IO | Ввод меняет память сразу; частые записи объединяются, при уходе приложения в фон выполняется flush |
| Повтор архива работал в цикле ViewModel | WorkManager, CoroutineWorker, Constraints, unique work, штатный backoff | Задание сохраняется отдельно от экрана, повторяется после временного сбоя и наблюдается через Flow |
| Общий busy связывал разные действия | Отдельные состояния экрана, чата и каталога | Навигация и оформление доступны во время запроса; повтор одной операции блокируется |
| Длинный чат создавал все карточки | Foundation LazyColumn со стабильными ключами | В тесте с 200 сообщениями за пределами экрана карточки не создаются; чтение истории не прерывается новым ответом |
| Все программы главного экрана и навигатора создавались сразу | LazyColumn по блокам программ, LazyRow в библиотеке | Одна общая вертикальная прокрутка главного экрана и сохранение состояния раскрытия |
| Офлайн-предупреждение закрывало вес и кнопки | Material 3 индикатор CloudOff и AlertDialog по нажатию | Постоянное состояние не появляется поверх чеклиста; Snackbar остаётся для результатов действий |
| Плеер вместе с таймером занимал слишком много места | Компактная панель с Material LinearProgressIndicator | Пауза, следующий трек и плейлист доступны; полная перемотка остаётся в плейлисте |

## Контракт и сохранность данных

Room schema 2 добавляет только локальную таблицу `local_drafts`.
AutoMigration 1 → 2 сохраняет планы и очередь подходов. Старые черновики из
`LocalDataStore` импортируются один раз, исходная копия сохраняется.
Цепочка: существующие поля API / локальный черновик → Room → состояние Compose.
Новых серверных полей, миграций или неподдерживаемых кнопок нет.

Сохранение черновика переживает закрытие диалога и ViewModel; небольшое окно
объединения ввода — 300 мс. `onStop` запускает сохранение оставшихся изменений
вне UI-потока. Жёсткое уничтожение процесса внутри этих 300 мс может потерять
последние символы; гарантия записи после подтверждённой транзакции остаётся у Room.

Ответ на отправленное сообщение не очищает уже набранный следующий черновик.
Обновление предпочтений не сбрасывает редактируемые поля анкеты. При выходе
запросы отменяются; позднее завершение старой операции не снимает блокировку
новой. WorkManager получает только hash аккаунта и читает текущую защищённую
сессию во время запуска. Задание другого аккаунта не выполняет HTTP-запросов.

## Оценка визуала

Главный экран сопоставлен с мобильным снимком веба и `ModernWorkout.tsx`:
сохранены порядок сводки, мышечного блока, веса и чеклиста, вложенное раскрытие
и типографическая иерархия. Основными источниками тесноты были перекрывающее
сообщение и суммарная высота таймера, плеера и навигации.

В чате уменьшены внутренние отступы, роль отделена небольшим заголовком,
сообщения пользователя выровнены справа. Поле и отправка размещены в одной строке.
На планшете ширина диалога ограничена; используются общие цвета, типографика и
Shapes приложения. Компоненты остаются Material 3, собственного движка чата нет.
С включённой экранной клавиатурой обнаружен сдвиг всего диалога за верх экрана.
Диалог переведён на явное edge-to-edge окно с системными отступами и
`WindowInsets.ime` через штатный `imePadding`. Тест дополнительно проверяет,
что заголовок остаётся виден в реальных экранных координатах.

Библиотека программ теперь прокручивается горизонтально и при большом шрифте,
вместо растягивания всего списка по вертикали. Названия имеют две строки и
ограничение ширины; переключение не меняет пользовательские данные.

Графики Vico/KoalaPlot, календарь Kizitonwose и полноразмерный плейлист Material 3
сохраняются. Их повторная отрисовка вручную не требуется.

Следующие визуальные приоритеты по просмотренным экранам:

1. Аналитика: собрать многочисленные фильтры в компактную панель Material 3,
   чтобы график быстрее попадал в область просмотра. Сводные карточки также
   занимают существенную часть первого экрана.
2. Настройки: группировать разделы и уменьшить высоту выбора оформления.
   Сейчас первая большая группа вытесняет профиль, музыку и данные далеко вниз.
3. Статистические подписи: единообразно локализовать числа, даты и формы слов.
   В существующих карточках ещё видны `81.25 кг`, ISO-даты и `1 подходов`.

Эти пункты обозначены как следующая переработка, а не как уже исправленные.

## Ограничения

Главная страница виртуализируется по программам. Внутри одной раскрытой программы
упражнения пока составляют общий блок: очень большая одиночная программа требует
отдельного профилирования и возможного разбиения на элементы ленивого списка.
Это ограничение не скрывается под заявлением о виртуализации каждого подхода.

Полная сверка каждого пользовательского сценария с вебом и измерение плавности
на физическом устройстве не завершены. Эмулятор с программным GPU не доказывает
60 fps. Публикации релиза нет.

Основа интеграции: [Room migrations](https://developer.android.com/training/data-storage/room/migrating-db-versions),
[WorkManager states](https://developer.android.com/develop/background-work/background-tasks/persistent/how-to/states),
[Compose lazy lists](https://developer.android.com/develop/ui/compose/lists).
